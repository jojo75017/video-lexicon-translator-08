# Architecture
- KDP launch plans reuse listMyBooks for saved manuscript metadata and the ASIN library for published books; only the title is required, so missing categories never block preparation or carry another book's metadata.
- Amazon Ads plans reuse the existing KDP advertising route and BYOK writing service, enforce three Sponsored Products campaign types and user-supplied competitor ASINs, and calculate optional simulations from explicit assumptions only, so preparation never starts spend or fabricates performance.
- Offer-page KDP Pilot upgrades reuse the shared external partner URL and promotion code, keeping partner subscriptions separate from EbookStudio checkout and entitlements.
- JVZoo review access uses admin-only creation of a new Auteur subscriber and an immutable auth app-metadata marker for scoped revocation, never payment records or existing customer updates.
- /outils-partenaires is presentation-only; /partenaires retains the affiliate programme. Neither changes entitlements or payments.
- V3 navigation groups category buttons separately from neutral admin actions, with scoped toolbar tokens so unrelated page controls retain their existing styles.
- Separate wrap image exports crop the shared full-cover renderer at each zone’s finished dimensions, preserving artwork and text without printing editor guides.
- Wrap layout templates transform existing text elements locally and preview through the export renderer, preserving content, private images, image adjustments and KDP geometry.
- Cover brightness limits match across controls, saving and export, so brightening survives printing.
- Wrap text formatting uses one shared canvas renderer, so exports and thumbnails keep block styles.

- Full-wrap illustrations use optional imageCoverage with shared preview/export placement, preserving front-only covers.

- HumanizeAI conserve la route `/v3/outils/humanizer` et centralise humanisation et audit stylométrique, afin de préserver les liens existants et une seule porte d’entrée.
- Studio Micro-Séries utilise le pack `micro_series` et le droit `micro-series`, vendus séparément de tous les forfaits, afin que la précommande V4 ouvre automatiquement l'accès futur.
- Le Studio Album Illustré 3–6 ans reste un module séparé des Histoires courtes et utilise un brouillon dédié, afin de préserver les recueils existants et la continuité d’une histoire unique jusqu’à 30 pages.
- The V3 home page exposes “Commence ici” as the primary subscriber entry point, so users reach specialist selection without searching through tools.
- V3 cards use `AgentPortrait` for consistent editorial-android portraits.
- BD scenarios read current writing-provider settings through a BYOK dispatcher with no provider switching; upstream failures stop generation and expose their safe reason.
- “Écrire un livre” uses the dedicated `/v3/lancer` direct-writing flow, while “Je raconte un livre” uses `/v3/create`, so their steps never appear identical.
- Launch emails share a Paris-date guard; audience counters use the sending function's status mode to preserve exclusions.
- The authenticated V3 home excludes acquisition content and groups every paid add-on after the useful studio sections, so subscribers see a workspace overview before optional purchases.
- The header library loads ownership-filtered metadata through a security-invoker function, excluding manuscript bodies and embedded image blobs to prevent timeouts without weakening RLS.
- The legacy /v3/hub page is admin-only via V3HubAdminOnly, redirecting clients to the equivalent current page so old links never expose the technical workshop.
- The subscriber cover studio (Studio V4) lives at /v3/studio-v4 as a standalone page reusing CoverStudioPro, so subscribers reach it without the legacy hub or the paid /v3/cover-pro offer.
- Cover Studio Pro access is decided server-side in hasCoverProRight (purchase or active Édition/Maison subscription), so UI gates never diverge from paid rights.
- Cover illustrations for subscribers without Cover Studio Pro use the shared included engine (`src/lib/cover-editor/includedCoverEngine.ts`, V2 `generate-ai-cover`) and store results in the private covers bucket, so the paid Pro pipeline and its credits stay untouched.
- Post-purchase one-time offers live on /oto/* and grant rights via v3-upsell-checkout packs + module_entitlements, so no new Stripe products are needed.

- Public pricing uses V3_LIFETIME_OFFERS while V3_PLANS remains historical subscription data, so new offers do not alter existing subscriber rights or billing.
- Home engine module badges reuse findPaidModuleForPath and useModuleAccess without granting rights; administrator access is distinguished from customer inclusion to avoid misleading paid-option labels.
- Dark homepage feature panels show access information immediately below their titles, separating included workflows from paid extensions through the shared access badge without changing permissions.
- New-customer offers (Auteur one-time, Édition lifetime) are sold through v3-pack-checkout plan ids and granted by payments-webhook (grantForPlan), with purchase_model=one_time on new sessions, so historical 47 € and annual subscription rights stay untouched.
- JVZoo sales enter through the jvzoo-ipn function (JVZIPN v2 cverify, product filter, unique event key) and only grant or revoke Auteur rights JVZoo itself created, so Stripe and other rights are never overwritten.
- Starter uses isStarter locks, never V2/Pro rights; /lancement and /lancement/offres reuse StarterPage and preserve payment query parameters to avoid divergent funnels.
- Shared writing policy separates guides from fiction; wizard outlines bypass P3 and resume checks include book type, preventing novel drift.
- VC Books navigation opens a presentation-only preview at /v3/vc-books/apercu using the supplied reference assets; its image studio remains separately gated, and writing and book exports stay explicitly upcoming so preview access never grants paid rights.
- VC Books images live at /v3/vc-books/images and reuse the included generate-ai-cover endpoint with a dedicated explicit illustration prompt, bypassing photographic concept generation without consuming Cover Pro credits or changing other studios.
- VC Books books are stored in the user-scoped `vc_books` table; the creation form (/v3/vc-books/creer) and library (/v3/vc-books/bibliotheque) feed the image studio via ?livre=<id>, which prefills title/author/theme and can save the generated cover back onto the book.
- VC Books KDP sheets are editable client-side drafts populated from the selected book, separate from image prompts and checkout prices, so metadata never changes artwork or billing.
- VC Books creation form offers fixed editorial idea chips from src/data/vcBooksIdeas.ts that fill the whole sheet (title, subtitle, theme, description, categories) on one click, so ideas stay hand-written lists and never generate content randomly.
- Toggle chips on V3 public pages carry `.v3-chip-toggle` (styled in src/styles/v3-public.css) because the blanket `.v3pub button` blue rule would otherwise paint selected and unselected states identically.

- New-offer checkout amounts live in _shared/newOfferPayments.ts with finite monthly installments; existing six-installment orders remain supported by the webhook but cannot be sold again.
- Installment invoices are claimed once through a service-role-only atomic function because Stripe can send both invoice.paid and invoice.payment_succeeded for one charge; orders are completed before cancellation to preserve access.
- VC Books writing uses the `vc-books-pauses` branch of generate-content with the shared BYOK comic dispatcher, storing pauses in `vc_books.pauses`; Word/PDF exports are generated client-side at the book's KDP trim size and model margins.
- The "/" root route sends visitors to the internal /commander tunnel, never to the dead external Landaa 47 EUR funnel; only authenticated users are routed to their space.
- Illustrated adult guides live at /v3/guides-illustres in the user-scoped `illustrated_guides` table, writing via the `illustrated-guide` generate-content branch (BYOK) and images via the included generate-ai-cover engine, so no paid credits or other studios change.
- Illustrated guides write with OpenRouter for admins and with each subscriber's chosen provider (Gemini default) otherwise; chapter and cover photos come from Unsplash/Pixabay via the stock-photos function (project keys, credited captions, Unsplash download tracking), with AI images kept as an option.
- Illustrated guide images (AI or stock) are uploaded to the ebook-images bucket via storeGuideImage and only their URL is saved, because inline data URLs bloated rows to 40+ MB and made guides time out on load and save.
